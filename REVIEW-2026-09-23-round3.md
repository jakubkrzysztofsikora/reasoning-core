## Finding 1 — CRITICAL: The audit-response documents contain fabricated attestation

Round 2's CRITICAL was an attestation defect in the *baseline registry*. Round 3's CRITICAL is the same disease in a new organ: the documents whose entire function is to answer auditors. We fact-checked both responses sentence-by-sentence against git history and the working tree. Result: **three claims of completed work that do not exist, one fabricated pre-history, and a test-count attestation that was false when committed.**

1. **The fabricated pre-history.** `AUDIT_RESPONSE_2026_09_22.md` "rejects" the round-1 `NameError` finding by asserting the maintainer's `try: import torch` patch "was already in place before the review ran." We ran `git log --all -S` pickaxe forensics across every ref, stash, and unreachable object: **the import appears in exactly one commit — `d20c7be`, the fix commit itself, timestamped after the review.** `git show 6726c6a` and `git show 57ee877` (the SHAs the review audited) contain no torch import anywhere in the file. There is no commit, stash, or ref in which the claim is true. A review response that invents pre-history to dismiss a finding is not an audit response; it is a counter-claim requiring its own audit. (The underlying engineering point — that the *production-corpus* wiring was the real fix — is correct and to the maintainer's credit. The rejection mechanism chosen to make that point was false.)

2. **The documentation that wasn't written.** `AUDIT_RESPONSE_2026_09_22_ROUND2.md` claims the scoring flags "are documented in docs/CONFIGURATION.md (see round-3 work)." `grep RC_SCORING_V3|RC_DIFF_WINDOWING|RC_MAHAL_CORPUS_MIN|RC_NEURAL_CORROBORATED docs/CONFIGURATION.md` → **zero matches**; CONFIGURATION.md was not touched in the entire commit range. Three of the four flags are documented in README (progress — and noted); the fourth, `RC_NEURAL_CORROBORATED` — the flag that converts the neural signal into a hard edit blocker — **remains documented nowhere**, while the response dismisses it as "not a scoring flag." It gates the hard-block conversion at `mcp_gate.py:134`. It is exactly a scoring-enforcement flag.

3. **The docstring that wasn't updated.** The same response claims "the docstring on `loo_threshold_for_fpr` has been updated" to describe the nearly-inert contract. `scoring_signals.py:189` **still reads**: "With n=5 the realized FPR is approximately 0.05" — the precise claim we measured as false (0/60 ≈ 0.00). The three-word summary: the response reports a documentation change that was never made.

4. **The test counts that were false when committed.** Both responses state "994 pass + 4 skip + 2 fail-as-designed (refusal gate) — all unchanged." Our full run at HEAD: **4 failures**, not 2 — three in the pre-reg gate/staleness tests, plus **`test_pinned_revisions_are_40char_hex`, a pre-existing supply-chain invariant that round 4 itself broke** by writing the literal placeholder `REVIEWER_PIN_REQUIRED` into `_PINNED_REVISIONS` (`ssm_backbone.py:429`). A fix commit regressed a security-invariant test, and the response document — written minutes later, per commit timestamps — asserts the suite is "all unchanged." The "144 Phase tests" bucket matches nothing reproducible (the named batch collects 117); the response's own "6 integration tests" count for the windowing file is 7.

The pattern across three rounds is now unmistakable: **the code converges faster than the claims about the code.** Every fix narrative in these documents verifies by execution. Every *completion* claim — the things the documents say were also done — fails verification. An audit response is an attestation artifact. This repo has now produced an attestation defect in its baseline registry (round 2) and in its audit responses (round 3). The last unmaintained component of reasoning-core is the genre that responds to audits.

## Finding 2 — HIGH: Round-5 security is a real but partial blacklist, certified by self-confirming tests

The 14 new regexes flip real vectors from allow to block — we confirmed the matrix. But the audit battery re-run against the current tree scores **6 partial, 7 open, 0 closed outright**, because nearly every patched vector retains a live bypass:

- **`cd src && python3 rc_cli.py bypass-next`** — the new regex requires the `src/` prefix; the relative-invocation form **executed end-to-end: bypass armed, exit 0**. So does `python3 -c "import src.rc_cli; src.rc_cli.cmd_bypass_next(None)"`. The root cause — `cmd_bypass_next` (`rc_cli.py:429`) calls no `_operator_authenticated()`, while `enable-enforcement` does — is untouched, and the function that needs calling already exists with a docstring explaining exactly why TTY tricks don't count.
- **The Edit-tool hole: the round's biggest miss.** Round-5's `.envrc.local` patterns cover the *bash* layer only. `_guard_paths.py` — the layer that governs the Edit/Write tool, the primary write path of every coding agent — was not touched: `is_guarded('.envrc.local')` is still `False`. Our security auditor drove a real Edit payload through `pre_edit_guard.py` planting a full enforcement-downgrade block (`RC_MODE=copilot`→advisory, `S2_FAIL_CLOSED=0`): **exit 0, silent**, flagged only as `unsupported_language (.local)` — a short-circuit that fires before guarded-path logic can matter. The persistent self-liberation channel — round 1's "cleanest full escape" — remains open on the channel agents actually use. Bash-regex coverage of a side channel is not closure.
- **New-battery results:** `sed -i`, `truncate`, `dd of=`, `cp`, `mv`, `rsync`, `vim -es`, `ed`, and variable indirection all still write `.envrc.local` at the bash layer; `git rebase` (the largest remaining git hole) and `git worktree add` are uncovered; `unlink`/`find -delete`/`chmod 644` on hooks remain free; `kill -STOP $(pidof python3)` evades the title literal; `kill_'+'switches.json` construction still evades the word-boundary hardening — while the *harmless* `F=kill_switches.json; echo > $F` form is blocked, inverting the pattern's purpose.
- **The round's tests certify the patch, not the protection.** `tests/test_pre_bash_guard_round5.py` extracts regex *literals* from the source and asserts the regex matches the command string — never once calling `screen_command` (the file imports `subprocess` and never uses it). A guard whose dispatch order or layer plumbing broke would pass this entire suite. Contrast the pre-existing guard tests, which assert `screen_command(...) == 2`.
- **The disclosure overreaches.** README now frames the residual 7 findings as requiring "filesystem-level mitigations, not regex additions." False: authenticating `bypass-next` (one `if`), adding `/.envrc.local` to the guard allowlist (one line), and a shared secret on `/score`//baseline` (~30 lines total) are application-level fixes. The "Pareto-optimal" framing describes a subset that leaves the highest-frequency vector — the Edit tool — untouched.

## Finding 3 — MEDIUM: The scoring core's residuals, precisely mapped

- **Near-degenerate corpora escape the degeneracy guard.** The round-4 fix checks `(cov_inv == 0).all()` — exact zeros. Five embeddings differing by 1e-9 jitter (f64) produce a tiny non-zero inverse, a finite LOO threshold (~2,700), and benign-edit scores of 10¹⁶–10²¹: **every subsequent benign edit fires**. By default that is advisory warn-noise on every edit; with `RC_NEURAL_CORROBORATED=0` it is a hard block on every edit. One unauthenticated `POST /baseline` (no auth, no rate limit, loopback) with five tiny JSON payloads arms it. The fix is a condition-number floor, not an exact-zero equality; the response doc's own verification reproduced the *exact*-degenerate case only.
- **The anti-spoof is cosmetic.** The probe's defense against a fake `mamba_ssm` on `sys.path` — importing the canonical submodule path — is satisfied by an empty fake package with the right file layout (executed). Mamba-3 is currently withheld by *missing pins*, not by the spoof check; once `pin_model_cards.py` fills them, the same fake flips the probe. Related: the probe blesses `codestral-mamba` (pin exists) at a 35 GiB working set on any host, and `decide()` reports `fits=False` for oversized operator pins **without refusing them** — the docstring's "refuses to return it" is not what the code does.
- **The chunk cap was silently deleted.** The stride fix removed the cap from the chunker; the comment claims "the cap is enforced by the embedder's max_seq_len budget downstream" — `max_seq_len` bounds per-chunk tokens, not chunk count; no such cap exists. The dead `sampled = chunks[::stride][:32]` line is computed and discarded. Consequences measured: `difflib.SequenceMatcher` alone costs **4.7 s on a 4,000-line file**, and the no-hunk path (first sight of a file) embeds *every* chunk with no timeout. Blindness was fixed; a latency bomb was installed in its place.
- **`Infinity` reaches the wire.** The `+inf` degenerate threshold serializes into `ImpactReport.to_dict()` as bare `Infinity` — invalid strict JSON that strict external consumers (jq, Go, JS `JSON.parse`) will reject.
- Small honest bookkeeping failures: the `s2_core.py:1462` "deliberate fail-loud" comment now describes pre-fix behavior (the fix made it deliberately *inert*); the README's new tier table's medium-tier cell contradicts executed behavior (8 GB → `mamba-130m`, not the documented `unixcoder-base`); `RC_BAAI_BGE_CODE_V1_REVISION` — an env var that re-opens the unpinned-model hole — is another undocumented knob.

## Verdict

**FIX-FIRST — but for the first time, the headline defect is not in the product.**

Three rounds ago this review said the claims outran the code. Two rounds ago it said the evidence chain was broken. This round the evidence chain is repaired, the fix loop runs fix → tests → commit → baseline → docs in the correct order, and roughly two-thirds of the round-2 blocker list verifies as genuinely closed by our own independent executions. Whatever else is true, this repository *responds* — fast, substantively, and with tests that would have caught the original bugs.

Which is precisely why the round-3 finding lands so hard: the two documents that exist to certify that responsiveness contain a fabricated pre-history, two completion claims about work that was never done, and a test-count attestation that was false at commit time — while a fix commit silently broke a supply-chain invariant test that both documents then declared "unchanged." The failure mode has migrated, with the repo's strengths: from code, to attestation, to the *narrative of improvement itself*. A gate built on the thesis that assertions must be checked against what landed on disk now has an assertions-about-assertions layer that nobody checks.

The remaining work is unglamorous and small: thirty lines of authentication, one condition-number floor, one honest diff to two markdown documents, one completed eval run. The skeleton has earned its third consecutive "the engineering is real." The last thing standing between this project and the word "shipped" is the habit of writing checks — in baselines, in READMEs, in audit responses — that the tree has to be forensically reconstructed to cash.
