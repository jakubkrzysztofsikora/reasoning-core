# reasoning-core: A Hostile Review

> **Independent review, 2026-09-22.** Four adversarial expert reviews (claims-audit, ML/scoring core, security, evaluation methodology), plus independent verification by execution: the full fast test suite (~925 tests), the embedder auto-picker, the guard regexes, the CLI auth paths, and the published statistics were all re-derived from the repository at commit `6726c6a` (with two uncommitted doc edits in the working tree). Every finding below carries a file:line citation or an executed reproduction. We tested the claims as if we were the attacker the tool says it exists to stop — because that is the threat model the tool itself chose.

---

## The pitch

**reasoning-core** (github.com/jakubkrzysztofsikora/reasoning-core, MIT, ~25k lines of Python) is a *local pre-edit gate for AI coding CLIs*. Every Edit/Write proposed by Claude Code, Codex, Gemini CLI, Kimi, Copilot CLI, or Vibe is routed through a local sidecar that runs cheap deterministic oracles (`py_compile`, `ruff`, `ast.parse`, a project rule file) and scores the diff against an "8-dim risk vector" powered by a Mamba state-space-model embedder. In the default advisory mode it warns; in an opt-in "copilot" mode it blocks the write before it lands. The README promises: loopback-only, no telemetry, six CLIs, millisecond oracles, self-calibration from your git history, and — unusually for this genre — a frank evidence-status box admitting that the benchmark numbers are historical and the current real-usage evidence is not yet built.

That last part is why this review exists. A project that markets epistemic honesty as a feature must be held to the standard it sells. We held it there.

**The one-paragraph verdict:** the deterministic skeleton is real, decent engineering; the audit-and-retraction culture is genuinely above the bar for a solo project; and the test suite passes. But the flagship ML feature shipped on 2026-09-22 **cannot execute at all**, the installer **actively bricks the gate on the high-RAM machines it targets**, the shell guard can be disarmed by the very agent it monitors through at least five unpatched first-attempt holes, and the headline "−49% cost" statistic — already soft from post-hoc cell selection — rests on a table that contains **an arithmetic error inside the retraction of a previous arithmetic error**. The repo's own evidence-status box is the most honest document in it. Everything arranged around that box keeps trying to bury it.

Verdict: **RETHINK the claims; the skeleton is worth keeping.**

---

## What is genuinely good

Credit first, because it is earned and it frames the failures as failures of execution against a standard the project itself set.

- **The deterministic oracle layer works.** Real `py_compile`, `ast.parse`, `node --check` (with sensible .mjs/.cjs handling), ruff/eslint scoped by extension, non-blocking timeouts, and a boot-time canary that proves each enabled oracle can still detect a planted finding. Measured latency: ~3 ms for syntax oracles, ~85 ms including ruff on a 587-line file. The "milliseconds, free" claim holds.
- **The audit-and-retraction culture is real.** `docs/BENCHMARKS.md` contains a formal data-integrity retraction: byte-identical T5/T7 rows identified as physically impossible, a P0 winner corrected *against the tool's own interest* (correcting it dropped the tool arm from 6/8 wins to 5/8), retracted numbers preserved in a labeled box rather than deleted, the retracting commit pinned. `docs/AUDIT_RESPONSE_2026_09_19.md` documents not only which hostile findings were accepted but which were *rejected, with mechanisms*. Most commercial projects never do this.
- **Several round-1/round-2 audit fixes verify in code.** `/score` is offloaded via `asyncio.to_thread` (`src/s2_core.py:1553`); `/baseline` likewise (`:1615`) with a test of exactly the promised name; the symlink resolver uses `os.path.realpath` and blocks on realpath hits; `install.sh` gates `direnv allow` behind an `ENVRC_GENERATED_BY_INSTALL` sentinel.
- **The bind claim is true.** `127.0.0.1` is hardcoded in the sidecar (`src/s2_core.py:1649`), the supervisor broker, and the launcher — not env-overridable. No telemetry code exists anywhere we looked.
- **Supply-chain posture is above average.** HuggingFace repo allowlist, `trust_remote_code=False`, 40-hex SHA revision pins, fail-closed on mutable refs, plus a `random-mamba` falsifiability control registered alongside real backends.
- **The suite passes.** We ran the documented fast gate: ~925 tests collected, 2 skipped, 2 failed — and both failures are the pre-registered "fail-as-designed" refusals in `tests/test_pre_reg_embedder_gate.py` that deliberately block a default-embedder flip until the Mamba-3 kernels exist. The two-failure state exactly matches the audit doc's own declaration. The regression suite is not decoration.

None of that, however, survives contact with the following.

## Finding 1 — BLOCKER: The flagship "independent signal" shipped 2026-09-22 cannot execute

Round 3 of the audit response declares RC-ML-04 *"closed by adding a non-redundant signal"*: a new `mahal_anomaly` field (Mahalanobis distance against a benign per-session corpus) in `src/scoring_signals.py`, wired into `score_change` under `RC_SCORING_V3=1`, covered by "22 new tests," and sealed with an immutable post-fix baseline. The README presents this as shipped work.

It is a no-op. Three independent kills, each verified:

1. **It raises `NameError` on every production call.** The on-the-fly fit branch (`src/s2_core.py:1166`) calls `torch.from_numpy(...)` — but `torch` is never imported in `score_change`'s scope. It is imported only inside `_cosine_similarity` (line 934), `_l2_distance` (line 957), and `_build_session_baseline_sync` (line 1027). The resulting `NameError: name 'torch' is not defined` is swallowed by `except Exception` at line 1195 and logged at `debug` level: *"Phase C mahal_anomaly failed (non-fatal)."* The field is silently `None`. Forever.
2. **It could never fire even if it computed.** The fired condition `mahal_anomaly_above_threshold` requires a threshold that nothing in production ever writes. `grep` across `src/`, `scripts/`, and `eval/` finds zero writers of `__mahal_threshold__` (or `__mahal_mean__`/`__mahal_inv__` outside the dead branch above). The `/baseline` endpoint writes only per-file vectors. `threshold_for_fpr` is imported by tests only.
3. **The tests cannot catch this because they seed production-impossible state.** `tests/test_scoring_v3_wiring.py:77-84` hand-writes the `__mahal_*__` keys into the session-baseline dict. No production path creates them. That is how 22 "Phase C" tests pass in under a second while the shipped feature does nothing.

And the statistics underneath are their own problem: `threshold_for_fpr` takes an in-sample quantile — the FPR is calibrated and evaluated on the same corpus. Measured: at n=5 the realized FPR is 0.20 (not 0.05); at n=2 the fitted threshold is *negative*; at n=1 — explicitly permitted by the validation code — the covariance collapses to zero and `mahal_anomaly` is +∞ for every edit. The docstring's "stable for n ≥ 5" is off by roughly two orders of magnitude of corpus size. "Independent by construction" is true only in the narrow sense that it is not a closed-form transform of the same cosine scalar; it consumes the same embedding from the same forward pass that already drives AIS, coherence-delta, and novelty.

**Why this matters beyond the bug:** the post-fix baseline `baseline-2026-09-22-scoring-v3-post.json` records an immutable manifest for a feature that never runs. RC-ML-04 is declared closed by a signal that does not exist at runtime. A project whose own AGENTS.md demands "do not represent synthetic scenarios as broad causal evidence" has represented a fixture-seeded test run as a shipped signal.

## Finding 2 — BLOCKER: `rc init` bricks the gate on exactly the machines it targets

The README's tier table says a ≥32 GiB host gets `mamba3-siso-1.5b`, and the audit response asserts: *"`rc init` correctly refuses to pick the 1.5b variant on hosts lacking the fast path."*

We executed the picker. On a 40 GB-RAM host:

```
>>> decide(available_ram_gb_value=40, available_disk_gb_value=200)
tier: xlarge, backend: mamba3-siso-1.5b
```

There is no loadability gate anywhere in `decide()` (`src/embedder_tier.py:229-314`) — only RAM and disk arithmetic. The same README admits the Mamba-3 checkpoints "cannot be loaded by the current transformers stack (no `Mamba3*` class)." So `rc init` writes `export RC_EMBEDDER=mamba3-siso-1.5b` into `.envrc`, and because the value now reads as an *operator pin*, `load_backbone` **refuses fallback** (`src/ssm_backbone.py:994-1003`): every `/score` returns 503, permanently, until the user hand-edits `.envrc`. In default advisory mode the gate degrades to warn-only with a dead neural layer; with `S2_FAIL_CLOSED=1` — the posture the hardening doc recommends — **every edit on the machine is blocked**. Bonus: `rc init` then dutifully downloads the multi-GB unloadable checkpoint from `state-spaces/mamba3-siso-1.5b@main`.

The irony is precise: the project's genuinely good supply-chain control (SHA pinning, fail-closed on `revision='main'`) is exactly what guarantees the auto-pick cannot load. A safety control fails **closed into a brick** on workstations, while the audit doc asserts the failure cannot happen. That sentence in `docs/AUDIT_RESPONSE_2026_09_19.md` is false against the code in the same repository.

## Finding 3 — MAJOR: Eight dimensions, one number, three percent of your file

The marketing layer sells an "8-dim risk vector." What the code computes is less, and sometimes other:

- **Three of the headline signals are one number.** `ais = (cos+1)/2`, `coherence_delta = √(2−2cos)`, `novelty = 1−max(cos,0)`. We verified the bijection numerically. With the default thresholds, `ais < 0.4` (cos < −0.2) is a strict subset of `cd > 0.09` (cos < 0.996), so the AIS condition can never fire without the CD condition having already fired — the code itself admits the double-fire in a comment (`s2_core.py:1290-1308`). Effective information content: **seven structural deltas plus one cosine**, dressed as eight dims plus AIS plus CD plus novelty plus drift plus three optional dims.
- **The "drift runaway" safety gate is dead.** `cumulative_drift` is chord distance, hard-bounded in [0, 2] by its own docstring (`s2_core.py:947`). The thresholds are `RC_DRIFT_WARN=4.0`, `RC_DRIFT_DENY=6.0` (`src/hooks/_dispatch.py:443-444`) — stale survivors of a pre-rescale metric. A threshold of 6.0 on a metric whose maximum is 2.0 never fires. The one exit-2 path that would have violated the "neural-only never blocks" policy is unreachable, which is lucky — because it was a live policy violation waiting, and nobody noticed it was dead.
- **The dims are named better than they are measured.** `fan_in`/`fan_out` are deltas of *whole-file* max call-graph degree with unresolved-name counting that includes builtins (`print`, `len` count as fan-out). `cyclomatic` is a count of tree-sitter branch-node types, not McCabe complexity. `churn` is a set symmetric difference of lines — we confirmed a 1,000-line full-file rewrite in reverse order scores churn 0. `novelty` appears twice: as a headline signal and as "dim 8" of the structural vector. The internal HOW_IT_WORKS table is honest about formulas; the README's labels oversell them.
- **The model sees ~3% of your file.** The 512-token truncation means the embedder consumes a prefix. Measured with the real tokenizer on this repo's own files: `s2_core.py` — 18,381 tokens → **2.8% embedded**; `_dispatch.py` 2.7%; `_oracles.py` 2.8%. The admitted "blinds past line ~40" is generous.
- **The truncation fix is dead code with a fictional API doc.** `embed_windowed` is called by nothing but its own tests. The module docstring documents a signature (`embed_windowed(text, lang, diff_hunks)`) that does not match the implementation. Yet the audit response marks RC-ML-Truncation "**Closed (infrastructure landed)**" — a closure claim about a consumer swap the same document admits is "staged for the next refactor PR." Production still truncates at 512 exactly as before.
- **The falsifiability control is one flake away from production.** When `RC_EMBEDDER` is unset and the default load fails transiently, the fallback chain walks remaining backends and can land on `random-mamba` — the deliberately random control — with only a log line to tell you your edits are now scored by noise (`src/ssm_backbone.py:1005-1028`).

## Finding 4 — HIGH: The gate cannot guard its own keys

The threat model, per the docs, includes *the monitored agent itself misbehaving on your machine*. Against that adversary, we found the disarm paths are guarded like the perimeter of a company whose front door is unlocked:

1. **`rc bypass-next` is unauthenticated, and the guard misses the obvious invocation.** `cmd_bypass_next` (`src/rc_cli.py:429-433`) sets the override with no `_operator_authenticated()` call — unlike `enable-enforcement`, which does authenticate. The bash guard blocks the strings `rc bypass-next` and `src.rc_cli ... bypass-next` (`src/hooks/pre_bash_guard.py:80-81`) under a comment claiming a "Reviewer-flagged P0" was closed. It was not: `python3 src/rc_cli.py bypass-next` — the plain path form — matches neither regex, and we confirmed `cmd_bypass_next` needs nothing but the ability to run a command, which is precisely the capability the threat model grants the agent.
2. **`.envrc.local` is completely unguarded — a persistent self-liberation channel.** The guarded allowlist (`src/hooks/_guard_paths.py:37-59`) protects `.claude/settings.json`, the hook sources, and `rules.yaml`. It does not contain `.envrc` or `.envrc.local`. Confirmed allowed: `echo 'export RC_MODE=advise' >> .envrc.local`. Enforcement mode is, structurally, an env block in those files — so the agent can flip every *future session* into warn-only with one append. This is the cleanest full escape in the repository: one line, not audit-noisy, survives restarts. The `guard-hash` integrity ritual covers `.envrc.local`, but it is post-hoc, operator-run, and the Stop hook that would automate it ships empty in this repo's own `.claude/settings.json`.
3. **Case-folding defeats the edit lock on macOS.** `is_guarded()` does realpath-then-case-sensitive-substring matching (`_guard_paths.py:144-158`). On APFS — case-insensitive, as shipped on every Mac — an Edit to `SRC/HOOKS/pre_bash_guard.py` misses the substring match yet lands on the real file. The symlink hardening (round 2) fixed case-*resolution* through symlinks; nobody folded case. Demonstrated on a scratch copy.
4. **The git rewrite family was blocked at one door of seven.** `git apply`, `git checkout <sha>`, `git restore`, `git stash apply` are blocked. Still allowed: `git stash pop` (the synonymous form of the blocked command — a trivial near-miss), `git cherry-pick`, `git revert`, `git am`, `git pull`, `git fast-import`, `git rebase`. Each rewrites working-tree files, including guarded ones.
5. **Deletion and process death are unguarded.** `unlink src/hooks/pre_bash_guard.py`, `find src/hooks -name '*.py' -delete`, `python3 -c "os.remove(...)"` — allowed; the guard's `rm` regex requires the literal `rm`. And the sidecar-protection token list matches script names (`s2_core`, `start-sidecar`) while the sidecar's actual process title is `reasoning-core-sidecar` (`src/s2_core.py:1678`) — so `pkill -f reasoning-core-sidecar`, and worse `pkill -STOP` (an unrevivable freeze), sail through.

To be fair to the project where it is fair: the docs *do* acknowledge some residual gaps (`xxd -r`, build-tool codegen), the audit response explicitly recommends sandboxing for real isolation, and several things are done right — the guard-path check is ordered *before* kill-switch consumption, `rc:skip` magic comments injected by the agent are refused, the uninstall manifest is path-anchored against pivot attacks, and the audit response's honest framing ("this is a tripwire, not a sandbox") is the correct one. But five unacknowledged first-attempt holes is not a tripwire with known gaps; it is a tripwire whose cradle was left open. There is also a structural confession the docs never make: the agent runs as the same user, the enforcement token is same-user readable, and `kill <pid>` is unblockable — so the ceiling of this design is *tamper-evidence and friction*, never confinement. The hardening doc should say so in its first paragraph, not in ours.

## Finding 5 — HIGH: The numbers, and an arithmetic error inside the retraction of an arithmetic error

The benchmark story is the repo's most self-aware artifact — and still its most self-undermining.

**The retraction contains a fresh error.** The surviving-5 aggregate table (published in both `docs/BENCHMARKS.md:131` and the whitepaper `results.tex:60`) reports Setup B plan quality **2.20** and Δ −1.20 (−35.3%). Recomputed from the doc's own per-task rows (1.0, 3.0, 5.0, 3.0, 1.0): the mean is **2.60**, Δ −0.80 (−23.5%). No weighting scheme reconciles 2.20 with the published rows; the error has survived two retraction commits. An organization that catches someone else's copy-pasted rows while miscomputing a five-row mean has a process problem, not a typo problem. (The other aggregates — cost, tokens, suite totals, the p=1.00 sign test — all recompute exactly. The sign-test implementation in `eval/stats.py` is correct.)

**What the surviving evidence actually says.** Strip the retracted cells, and the table reads: the gated arm produced **worse plans (3.40 → 2.60), worse implementations (3.20 → 2.80), and spent less money (−49%)**. That is the honest headline: *the gate's arm writes worse code cheaper, on n=1–3 post-hoc-surviving cells, with p = 1.00.* The document instead bolds the cost row, buries the quality rows, and appends a suite-total callout ("$25.32 / 49% lower") before the p-value. The cells survived because they were internally self-consistent — selection on the dependent variable, the textbook winner's curse — and the one retracted row with surviving context (P0) had the gate arm at 2.5× the cost.

**The dollar table contradicts the evidence box forty lines later.** The evidence-status box says the figures "must not be presented as current real-usage quality, cost, or regression evidence." `docs/BENCHMARKS.md:51-57` then presents a token-savings arithmetic denominated in dollars: "100 tasks/month ≈ $9. 1,000 ≈ $90. 10,000 ≈ $900." A hedge is not a hedge if the hedged number is extrapolated into a purchase decision below it. The whitepaper abstract still leads a seven-bullet benefit list with the same figures; the three registry-submission boilerplates carry the "8.2% token savings" with no hedge at all — and those are the files that get pasted into listings.

**The strongest-looking number is a stale sentinel.** The "κ=0.8025, gate_pass=true" grounding result cited in BENCHMARKS is not a hardcoded test sentinel (we checked; it recomputes from committed per-judge labels — to the project's credit). It is, however, a single run from 2026-05-06 whose CI lower bound (0.697) barely clears the 0.7 aspirational gate — and `_plan_quality.py:148-159` reads that four-month-old file **at runtime, with no staleness check**, to gate live behavior.

**Four pre-registrations, zero completions.** SWE-bench n=100 (EVAL_DESIGN), 5-arm human-labeled n=100 (EVAL_PROTOCOL), the 8-task iter-2 sign-test ladder, and the Kimi preregistered 8-pair study. The first two have never produced a live data point; the third awaits "additional ≥3 cells of n≥3 evidence"; the fourth *abandoned its preregistered lexicographic endpoint* mid-experiment (Amendment 1 changed the treatment after Arm B started; all artifacts, including the "frozen" preregistration, were committed in a single batch ~24h after execution — nothing in the repo can prove amendment ordering), substituting scenario-detection rates and a Monte-Carlo simulation whose "10× variance compression" headline is a simulation output presented with measured-result typography.

**And the loop is closed.** Calibration labels come from one author's commit-message prefixes, mined from this repository, whose history includes developing the gate itself; eval tasks are authored by the same author who writes the gate rules and the ground truth. The calibration-defining threshold change (0.5 → 0.09, commit `135f801`) predates the baseline registry and cites an uncommitted 197-event audit. Every internal "the gate fires correctly" number lives inside one person's epistemic closure. That does not make the numbers fake. It makes them uninterpretable as generalization evidence — which is exactly the claim the marketing keeps reaching for.

## Finding 6 — MEDIUM: The documentation-debt ledger

Individually small; collectively a pattern of README-by-aspiration:

- **"Six CLIs" is contradicted by the README's own quick start, which lists seven** (`pi` included), and by `rc init`, which installs seven.
- **"Pulls the 250 MB mamba-130m checkpoint up front" at pip-install time is impossible** — a stock setuptools wheel runs no such code; the model downloads at `rc init`, step 2, not step 1. An offline user following the README gets a degraded gate.
- **The README's canonical block example cannot occur.** It shows a ruff block for an unused import; the ruff oracle *skips findings that have auto-fixes* (`_oracles.py:402-404`), and F401 has one. Also `tempfile` is in fact used in the file the example cites. The docs' own screenshot is staged.
- **The audit response documents an API that does not exist**: `detect_tier`/`pick_backend` (`embedder_tier.py` ships `decide`/`fits`); the README's tier table also mismatches behavior — at 10 GB the code picks `mamba3-mimo-894m`, not the documented `mamba3-siso-893m`.
- **"110 tests" (round 1) vs "905 passed" (round 2)** measure different scopes under the same label, one day apart — arithmetically impossible as written.
- **`rc upgrade --ref v0.3.0` advertises a tag that does not exist** in the local repo; PyPI serves **0.4.0** while the repo's pyproject says **0.3.0** and the committed wheel in `dist/` is a stale **0.2.0** that predates the RC-ML-05 fix the docs claim it embodies.
- **The installed package is literally named `src`** — `from src.s2_core import score_change` works, and collides with any other project shipping a top-level `src` package. In the year 2026, shipping a package named `src` is a choice.
- **`rc audit-history`'s "fix/revert/hotfix" is actually `fix|revert|hotfix|patch`** — a README-only commit saying "patch docs" can flip a benign commit into a negative calibration label.
- **"No ongoing network calls" is slightly overstated**: fallback loads can pull additional HF checkpoints, and `S2_ALLOW_REMOTE=1` permits shipping source to a non-loopback endpoint on one env var. The loopback default and absence of telemetry are genuine; the absolutist phrasing is not.

## What would change our verdict

Ordered by leverage:

1. **Delete or actually wire the flagship.** Either make `mahal_anomaly` run (fix the import, write the threshold, add a production-path integration test that does not seed fixture state) or retract the RC-ML-04 closure and the scoring-v3 post baseline. A dead feature wearing an immutable baseline is worse than no feature: it manufactures false confidence.
2. **Gate the auto-picker on loadability.** One capability check in `decide()` — is there a pinned SHA, can the class be imported — plus a correct audit-response sentence. Until then the tier table should advertise `mamba-130m` everywhere and nothing else.
3. **Authenticate the disarm paths and guard the keys.** `_operator_authenticated()` on `bypass-next`/`skip-file`/`confirm-next`; add `.envrc`, `.envrc.local`, and the kill-switch state path to both guard lists with case-folded matching; extend the git family (`stash pop`, `cherry-pick`, `revert`, `am`, `pull`, `fast-import`); match the real process title; and state in HARDENING.md's first paragraph that this is friction and tamper-evidence, not confinement against a same-user agent.
4. **Fix the retraction's own arithmetic** (2.20 → 2.60, Δ −0.80/−23.5%) everywhere it appears, and re-order the surviving-5 table so the quality losses are typographically equal to the cost win. Delete the dollar-extrapolation table or watermark it as historical hypothesis-generation, and sweep the whitepaper abstract and the three submission boilerplates of unhedged numbers.
5. **Run one preregistered study, end to end.** One — with the endpoint as written, amendments pre-unblinding only, and the result published whatever it is. Four frozen plans and zero executions is process cosplay; a single honest n=8 null result would be worth more than everything currently in `docs/BENCHMARKS.md`.
6. **Put an expiry on the κ sentinel, and a staleness check on drift thresholds that cannot exceed their metric's range.** A threshold above the metric's maximum should trip a boot-time assertion, not wait for a hostile reviewer.

## Verdict

**RETHINK (the claims). KEEP (the skeleton).**

reasoning-core is a paradox worth publishing precisely because it is *not* vaporware. The oracles are real, the audit plumbing is real, the retraction culture is real, and ~925 passing tests is real. A solo developer built a working tripwire, documented its own audit trail better than most funded teams, and corrected evidence against their own product's interest. That is rare and it deserves to be said.

But the project currently fails the exact test it sets for itself in AGENTS.md: *deterministic policy checks are the only standalone hard-block sources, and synthetic or unverifiable evidence must not be represented as causal.* The 2026-09-22 "shipped" signal is synthetic in the most literal sense — it exists only in test fixtures. The auto-sizer ships a configuration the codebase itself documents as unloadable. The guard's P0 closure comment is falsified by a one-line invocation. And the benchmark document that certifies its own past dishonesty contains a fresh unexplained number in its corrected table.

The repo's evidence-status box — *"they must not be presented as current real-usage quality, cost, or regression evidence"* — is the most honest sentence in the repository, and it is accurate. The failure mode is not deception by statement; it is architecture: benefit lists, bolded savings, dollar tables, and registry submissions arranged so that the hedges lose on skimming. A reader who reads the boxes and a reader who reads the tables will walk away with opposite conclusions, and the document design has chosen — consciously or not — to let both exist.

For a gate whose entire thesis is *distrust what the model tells you and verify what lands on disk*, the standard is not "better than average." The standard is the one the README writes for others. Right now, reasoning-core does not meet its own.
