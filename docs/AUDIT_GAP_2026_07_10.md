# Audit: Why production showed only 4.1% reasoning-quality blocks

**Date:** 2026-07-10  
**Scope:** `src/hooks/pre_edit_guard.py`, `src/hooks/_dispatch.py`, `install.sh`, `.envrc`, `.envrc.local`, local audit log (`~/.local/share/reasoning-core/events/`).  
**Source of the 4.1% figure:** `thoughts/shared/plans/2026-07-09-reasoning-core-game-changer-upgrade.md` §1.1 — production audit of 68,794 events (2026-06-01 → 2026-07-08): 904 hard blocks, of which 37 (4.1%) were reasoning-quality blocks (`regression_detected`, `plan_impl_drift`, `decomposition`). 66.6% were self-protection / shell-escape / guard-file / lang-lock blocks.

The local ratio (6.8%) is in the same ballpark as the production 4.1%, but the absolute numbers are too small and too test-heavy to be statistically comparable. The important finding is that the **same causal mechanisms** are visible locally.

## 2. Root causes

### 2.1 `RC_MODE=advise` is the dominant cause

`.envrc:81` and `install.sh:158` both default to:

```bash
export RC_MODE="${RC_MODE:-advise}"
```

`pre_edit_guard.py:_apply_mode()` (lines 366–392) downgrades every `exit_block` and `continue_pair` outcome to `stderr_only` / `audit_only` in advise mode. This means contract, oracle, rule-engine, plan-grounding, drift, and SSM regression blocks **never exit 2** unless the operator explicitly runs `rc enable-enforcement`.

**Fix:** enforcement requires `RC_MODE=copilot`. One-line activation:

```bash
rc enable-enforcement   # writes .envrc.local with RC_MODE=copilot
```

or manually in `.envrc.local`:

```bash
export RC_MODE=copilot
```

### 2.2 `RC_SHADOW_MODE=1` turns blocks into shadow audits

`.envrc:82` / `.envrc:116` and `install.sh:159` default to:

```bash
export RC_SHADOW_MODE="${RC_SHADOW_MODE:-1}"
```

`_shadow_mode.is_active()` returns `True` when `RC_SHADOW_MODE == "1"`. In `pre_edit_guard.py` and `_dispatch.py`, a shadow-active gate converts `exit_block` into `continue_pair` → the edit proceeds and only a `shadow_blocked` audit row is emitted. This is **independent of `RC_MODE`**: even a copilot-mode session still logs shadow blocks instead of hard blocks while `RC_SHADOW_MODE=1`.

**Fix:** disable shadow mode in `.envrc.local`:

```bash
export RC_SHADOW_MODE=0
```

### 2.3 Plan-grounding is warn-only by default

`.envrc:151` and `install.sh:167` set:

```bash
export RC_PLAN_GROUNDING="${RC_PLAN_GROUNDING:-1}"
```

`_dispatch.py:gate_plan_grounding()` treats `mode == "1"` as warn-only (`stderr_only`) and `mode == "2"` as hard block. With the default of `1`, every `plan_impl_drift` or contract violation becomes a warning, not a block. Local logs confirm this: 631 plan_grounding events but only 16 blocked, and those 16 likely come from guard-file-like paths or copilot-mode test runs.

**Fix:** switch to hard-block in `.envrc.local`:

```bash
export RC_PLAN_GROUNDING=2
```

### 2.4 Oracles are advisory-only by default

`pre_edit_guard.py:955` only blocks on oracle failures when **both** of the following are true:

```python
_rc_mode() != "advise" and os.environ.get("RC_ORACLE_BLOCK") == "1"
```

`install.sh` and `.envrc` do **not** set `RC_ORACLE_BLOCK`, so it defaults to unset/`0`. The T1/T2 oracles run, but they only emit warnings. This is the direct reason execution-grounded oracles contribute almost no hard blocks.

**Fix:** in `.envrc.local`:

```bash
export RC_ORACLE_BLOCK=1
```

### 2.5 PRM gate is disabled by default and gated by promotion

`_dispatch.py:gate_prm()` returns immediately unless `RC_PRM_GATE=1`. Default is `0` (`.envrc:157`). Even when enabled, blocking requires `RC_PRM_BLOCK=1` **and** promotion criteria (≥2 weeks, ≥1000 events, ≥5 installs) to be met. The production audit recorded zero `signal_source=prm` events.

Note: `pre_edit_guard.py` **does** call `_handle_prm_outcome()` at line 1324 in the current code, so the gate is wired; it is simply never activated by default.

**Fix:** to collect PRM shadow data:

```bash
export RC_PRM_GATE=1
```

To allow blocking after calibration:

```bash
export RC_PRM_GATE=1
export RC_PRM_BLOCK=1
```

### 2.6 `RC_PLAN_BLOCK=0` lets plan-doc warnings through

`.envrc:83` and `install.sh:160` default to:

```bash
export RC_PLAN_BLOCK="${RC_PLAN_BLOCK:-0}"
```

`pre_plan_guard.py` only escalates plan-write warnings to `exit 2` when `RC_PLAN_BLOCK=1`. With the default, an agent can write a vague or oversized `PLAN.md` without the gate blocking it.

**Fix:** in `.envrc.local`:

```bash
export RC_PLAN_BLOCK=1
```

### 2.7 Missing `PLAN.md` silently disables plan-grounding

`_dispatch.py:gate_plan_grounding()` (lines 204–217) emits an `audit_only` event with `reason=no_plan_md` and returns `pass` when `PLAN.md` is absent. Local logs show 181 such events (4.4% of all events). Because the gate continues, the edit is allowed even though the lever is nominally on.

**Fix:** `rc enable-enforcement` requires an existing `PLAN.md` (operator-authenticated). For existing repos, write a `PLAN.md` manually, then run:

```bash
rc enable-enforcement
```

A fabricated plan is worse than no plan; the gate refuses to enable enforcement
unless a real plan exists.

### 2.8 SSM sidecar is mostly fail-open

`.envrc.local:12` sets:

```bash
export S2_FAIL_CLOSED=0
```

When the sidecar is unreachable or the `S2_HARD_CAP_MS=1500` cap is exceeded, `pre_edit_guard.py` falls back to symbolic gates only on `hard_cap_exceeded`; on other sidecar errors it exits 0 (fail-open) because `S2_FAIL_CLOSED=0`. The production audit reported 87.7% of SSM-tagged events failing open/closed rather than returning a score.

**Fix:** to make the sidecar fail-closed:

```bash
export S2_FAIL_CLOSED=1
```

This is already the `.envrc` default (`S2_FAIL_CLOSED=1`), but `.envrc.local` overrides it to `0`.

### 2.9 Phase-2 risk dimensions never emit

`src/s2_core.py` exposes `/baseline` (line 1288), but `pre_edit_guard.py` never POSTs to it. Without a baseline call, the sidecar cannot compute `session_centroid_drift`, `project_fan_in`, or `project_coupling`, so those risk-vector dimensions are zeros. The production audit found the marketed 11-dim vector in only 8 of 68,794 events and `architectural_impact_score` in zero.

**Fix:** call `/baseline` at session start (e.g., from `session_start_manifest.py` or `pre_edit_guard.py` on first edit), or remove the dimensions from marketing/docs if they are not wired.

### 2.10 Hook invocation gaps

`install.sh` registers `pre_edit_guard.py` only for `Edit|Write|MultiEdit`. Other high-leverage tools (`Task`, `Bash`) use separate guards (`pre_task_guard.py`, `pre_bash_guard.py`) that do not run the contract/oracle/PRM chain. An agent can bypass the reasoning-quality gate by using `Bash` to write files, unless the bash guard independently catches it (which it does only for shell-escape / self-protection patterns).

**Fix:** route `Bash` and `Task` edits through the same contract/oracle path, or document that reasoning-quality enforcement applies only to `Edit/Write/MultiEdit`.

### 2.11 Installed defaults contradict marketed defaults

`README.md:105–119` describes enforce-by-default behavior and plan-grounding-on. `install.sh:154–172` ships `RC_MODE=advise`, `RC_SHADOW_MODE=1`, `RC_PLAN_BLOCK=0`, and leaves `RC_PLAN_GROUNDING=1` (warn-only). The benchmark wins cited in the plan came from Setup B where these levers were explicitly enabled.

**Fix:** run the honesty patch documented in `thoughts/shared/plans/2026-07-09-reasoning-core-game-changer-upgrade.md` §4 Phase 0 — either change the install defaults to match the README, or rewrite the README to match the code. Do not leave both in contradiction.

## 3. Recommended minimum activation set

For a repo that wants reasoning-quality blocks instead of warnings, `.envrc.local` should contain:

```bash
# >>> reasoning-core enforcement >>>
export RC_MODE=copilot
export RC_SHADOW_MODE=0
export RC_PLAN_BLOCK=1
export RC_PLAN_GROUNDING=2
export RC_ORACLE_BLOCK=1
export RC_RULE_ENGINE=1
export S2_FAIL_CLOSED=1
# export RC_PRM_GATE=1      # optional: collect PRM shadow data
# export RC_PRM_BLOCK=1     # optional: after PRM is calibrated/promoted
# <<< reasoning-core enforcement <<<
```

Then:

```bash
direnv reload   # or: source .envrc.local
rc status       # confirm RC_MODE=copilot and expected lever states
```

## 5. Bottom line

The 4.1% reasoning-quality block rate is not a bug in the contract/oracle/PRM code; it is the **expected outcome of the shipped defaults**. Every reasoning-quality lever is either off (`RC_PRM_GATE=0`, `RC_ORACLE_BLOCK=0`), warn-only (`RC_PLAN_GROUNDING=1`), shadow-logged (`RC_SHADOW_MODE=1`), or downgraded by mode (`RC_MODE=advise`). The product as installed is a symbolic self-protection gate; turning it into a reasoning-quality copilot requires deliberate operator activation via `rc enable-enforcement` or the `.envrc.local` block above.
