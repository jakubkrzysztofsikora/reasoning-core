# reasoning-core enforcement pilot — 2026-07-10

## Purpose

Promote the local reasoning-core repo from `RC_MODE=advise` (log/warn only) to
`RC_MODE=copilot` (block on contract/oracle/rule failures) and enable hard
plan-grounding blocks (`RC_PLAN_GROUNDING=2`). Measure the impact over 48 hours
before deciding whether to keep enforcement, roll back, or tune thresholds.

## Activation

The required overrides are staged in `.envrc.local` (gitignored) so they are not
pushed and must be activated intentionally by the operator:

```bash
cd /Users/jakubsikora/Repos/personal/reasoning-core
direnv reload          # sources .envrc.local
rc status              # confirm RC_MODE=copilot and RC_PLAN_GROUNDING=2
```

Expected status:

- `RC_MODE=copilot`
- `RC_SHADOW_MODE=0`
- `RC_PLAN_GROUNDING=2`
- `RC_PLAN_BLOCK=1`

If `direnv` is not in use, source `.envrc.local` manually in every shell:

```bash
source .envrc.local
```

## 48-hour measurement plan

### What the operator runs

Run these commands at the start, once per day, and at the end of the 48-hour
window. All commands are read-only and safe to run repeatedly.

| Time | Command | Why |
|---|---|---|
| T+0 | `rc status` | Baseline posture check. |
| T+0 | `rc benchmark --days 1 --output pilot/baseline.md --json pilot/baseline.json` | Pre-enforcement baseline for the last 24 h of advise-mode data. |
| T+0 | `direnv reload` | Activate enforcement from `.envrc.local`. |
| T+0 | `rc status` | Confirm copilot mode is active. |
| T+24h | `rc benchmark --days 1 --output pilot/day1.md --json pilot/day1.json` | First 24 h of enforcement. |
| T+48h | `rc benchmark --days 2 --output pilot/day2.md --json pilot/day2.json` | Full 48 h enforcement window. |
| T+48h | `rc audit-history --days 2 --reasons` | Surface commits followed by fix/revert/hotfix (negative signal). |
| Ad hoc | `rc explain <decision_id>` | Deep-dive any surprising block. |

Store reports in a local `pilot/` directory (gitignored by default if you add it
to `.gitignore`, or keep it outside the repo).

### What `rc benchmark` reports to capture

Save both the Markdown report and the JSON metrics for each snapshot. Focus on
these fields when comparing baseline vs. enforcement:

| Metric | Interpretation |
|---|---|
| `total_events` | Volume of gated edits. Should stay stable; a large drop means the agent is avoiding edits or being blocked early. |
| `blocked` | Hard blocks in copilot mode. Baseline should be near-zero; enforcement should show contract/oracle/rule blocks. |
| `warn` | Advisory events. Plan-grounding warnings should move to `blocked` when `RC_PLAN_GROUNDING=2` is active. |
| `shadow_blocked` | Should be zero in enforcement (`RC_SHADOW_MODE=0`). Non-zero means shadow mode is still on somewhere. |
| `fail_open` | Sidecar/load failures that fell open. Watch for spikes that indicate infra problems. |
| `allowed_via_override` | Operator overrode a block and the edit was later allowed. A rising count signals false positives. |
| `retry_after_block` | Agent retried after a block. Expected and healthy; spikes with few successful retries suggest confusing blocks. |
| `scope_creep_catches` | `plan_impl_drift` + `contract_violation`. The primary signal that plan-grounding/contract enforcement is working. |
| `false_positive_proxy` | `(retry_after_block + allowed_via_override) / (blocked + warn + shadow_blocked)`, capped at 1.0. Target < 0.25 for the pilot. |
| `severity` breakdown | Check that `contract`, `oracle`, `rule_engine`, and `plan_grounding` classes are represented; dominance of `other`/`self_protection` suggests misconfiguration. |
| `median_block_latency_ms` | Should stay under the S2 hard cap (1500 ms) plus symbolic fallback overhead. p95 spikes warrant investigation. |
| `override_survival_ratio` | Fraction of overridden blocks that survive (are not reverted). Low values mean overrides were false positives. |

### Operator diary

For each block that feels wrong, record:

1. Decision id (`rc explain <id>`).
2. What the agent was trying to do.
3. Whether the block was correct, a false positive, or noisy.
4. Whether an override was used and the outcome.

This qualitative log is the input to the rollback/sustain decision.

## Rollback triggers

Roll back to `RC_MODE=advise` (or restore the previous `.envrc.local` state) if
any of the following happen during the 48-hour window:

| Trigger | Action |
|---|---|
| `false_positive_proxy` ≥ 0.5 on either day. | Roll back to advise; tune thresholds or fix contract/oracle labels. |
| `allowed_via_override` ≥ 3 per day. | Roll back; blocks are being overruled too often. |
| `fail_open` spikes to > 10% of events. | Roll back; infrastructure is not ready for fail-closed enforcement. |
| `shadow_blocked` > 0 after activation. | Roll back; `RC_SHADOW_MODE` is not being respected. |
| Median block latency > 5 s or p95 > 15 s. | Roll back; latency is hurting the agent loop. |
| Any edit that was blocked and then overridden is reverted within 48 h. | Roll back; strong false-positive signal. |
| Operator qualitative log shows ≥ 2 clearly-wrong blocks in a single session. | Roll back; trust is eroding faster than metrics can capture. |

To roll back:

```bash
# Option A: disable the enforcement block in .envrc.local (comment out the
# RC_MODE/RC_SHADOW_MODE/RC_PLAN_GROUNDING/RC_PLAN_BLOCK lines) and reload.
# Option B: one-shot bypass for the next blocked edit:
rc bypass-next
```

## Success criteria

After 48 hours, keep enforcement if:

- `false_positive_proxy` < 0.25.
- `scope_creep_catches` ≥ 1 (plan-grounding/contract enforcement is catching real drift).
- `fail_open` < 5% of events.
- No operator-reported clearly-wrong blocks.
- Block latency p95 ≤ 5 s.

If the criteria pass, the next step is to consider `RC_ORACLE_BLOCK=1` (currently
left at its default of `0`, so oracle failures only warn even in copilot mode)
and a broader rollout to sibling worktrees.

## Notes and caveats

- `.envrc.local` is gitignored and must not be committed. The enforcement block
  is staged locally only.
- `S2_FAIL_CLOSED` remains at the value already set in `.envrc.local` (`0` at
  the time of writing). For a production enforcement posture, ensure
  `S2_FAIL_CLOSED=1` so sidecar unavailability blocks rather than warns.
- This pilot covers only this repo. Other worktrees or eval setups need their
  own `.envrc.local` activation.
- The 48-hour window is a minimum. Extend if event volume is low (< 20 events
  per day) or if the operator needs more samples to judge false positives.
